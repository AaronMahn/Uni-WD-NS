# WD-NS: a unified RMF framework for white-dwarf and neutron-star matter

Code accompanying the paper

> **White dwarf–neutron star matter transition and the effect of light elements**
> Yao Ma, Yong-Liang Ma, Ruo-Xi Wu, Yue-Liang Wu
> *(arXiv link to be added)*

The framework treats white dwarfs and neutron stars — and the transition between
them — within a single relativistic mean-field (RMF) Lagrangian. White-dwarf
matter is solved self-consistently as spherical Wigner–Seitz cells (nucleus +
electron gas, full electromagnetic interaction), the same Lagrangian yields the
uniform matter of the neutron-star interior, and fixed-A neutronization
sequences are connected through exact Maxwell junctions. TOV integration of the
resulting equations of state gives the complete WD-to-NS mass–radius relation
for sequences seeded by ⁴He, ¹²C, and ¹⁶O.

## Layout

The code has three layers:

**1. RMF Wigner–Seitz cell solver** — `producting_Wdf_core.py` (class
`rmftorch`). Solves the coupled σ, ω, ρ, and photon field equations for a
spherical Wigner–Seitz cell on a 1D radial grid. Built on PyTorch: the nucleon
density profiles are `nn.Parameter`s and the total cell energy is minimized
with Adam, so field gradients come from autograd. The solver is driven by the
notebooks in `producting_Run/` (one each for ⁴He, ¹²C, ¹⁶O); converged model
checkpoints used as warm starts are provided in
`producting_Run/results/parameter/`. `module.py` contains shared utilities.

**2. Neutronization + Maxwell construction** — `eos_maxwell_connect.py`.
Connects the EoS branches of different nuclear composition (the fixed-A
neutronization sequence (Z,N) → (Z−1,N+1) → … and the uniform RMF matter of the
NS core) into a single cold EoS by an exact Maxwell construction:
p_A = p_B and μ_A = μ_B at each junction, with the stable branch chosen by
maximum pressure at given μ. Rest-mass conventions between branch tables are
auto-detected and unified.

**3. TOV integration** — `tov_dense.py` (interpolated EoS + RK4 TOV solver)
driven by `run_dense.py`, which produces the dense mass–radius tables
`results/mr_dense_*.dat` from the connected EoS tables. `tov.py` (numba-jit
integrator), `tov_MR.py`, and `multithreadtov.py` (multiprocessing pool over
EoS tables) are the general-purpose TOV utilities used elsewhere in the
workflow.

Development tools (beyond the paper pipeline):

- `pro_producting_Wdf_core_v2.py` — extended cell solver supporting separate
  proton/neutron masses (`M_p`, `M_n`); the variant used for the
  per-composition production runs along the neutronization sequences.
- `uniform_eos.ipynb` — generates the uniform RMF nuclear-matter EoS
  (i.e. regenerates `eosdata/eos_rmf.dat`) from a `modelpar` set via `module.py`.
- `Find_Par/` — notebooks for fitting RMF coupling constants to nuclear-matter
  properties (used to obtain the NN1-type parameter sets).

Figure scripts:

- `make_fig_maxwell_C12.py` — Fig. 1 (Maxwell construction across the ¹²C
  neutronization sequence, p–μ and p–ε planes) from `eosdata/eos_c/` and
  `eosdata/eos_rmf.dat`.
- `make_figs_eos_mr.py` — Figs. 2–5 (EoS panels with transition jumps; M–R
  relations: NN1 vs TM2 comparison, He/C/O panels, and the complete WD-to-NS
  relation with the historical HWW benchmark and WD/NS observations) from
  `eosdata/eos_maxwell_pmu_*.dat`, `results/mr_dense_*.dat`, and `input/`.

Figures are written to `figures/` (override with the environment variable
`WDNS_FIG_DIR`).

## Data

- `eosdata/eos_maxwell_pmu_{He,C12,O16}.dat` — the final Maxwell-connected
  WD-to-NS EoS for each seed nucleus (NN1 parameter set); columns
  `n_B [fm⁻³], p [MeV fm⁻³], ε [MeV fm⁻³]`. `eos_maxwell_pmu_He_TM2.dat` is the
  He-seeded EoS with the TM2 parameter set.
- `eosdata/eos_rmf.dat` — uniform RMF nuclear matter (NS core branch).
- `eosdata/eos_c/eos_Z,N.dat` — per-composition Wigner–Seitz EoS tables along
  the ¹²C neutronization sequence, (6,6) → (11,1), used by the Maxwell figure
  and construction. (The corresponding He and O16 sequence tables, and per-cell
  density profiles, are not shipped for size reasons; they are regenerated by
  the `producting_Run/` notebooks + `eos_maxwell_connect.py`.)
- `results/mr_*.dat` — TOV outputs: dense M–R tables (`mr_dense_*`, columns
  `n_c [fm⁻³], R [km], M [M_⊙]`), coarse/validation tables (`mr_pmu_*`), and
  smooth-branch tables (`mr_smooth_*`).
- `input/` — observational and historical comparison data: Gaia and Hipparcos
  white-dwarf M–R points, the Hartle & Thorne (1968) nonrotating HWW curve, and
  the BPS EoS table used for low-density crust comparison.

## Model parameter sets

The RMF coupling constants are set in the `modelpar` dict at the top of each
`producting_Run/` notebook, in code units (energies in HMeV = 100 MeV,
`echarge` = e in natural units). Both sets used in the paper are given there:

| parameter | NN1 ("AI") | TM2 |
|---|---|---|
| M (nucleon) | 9.38 | 9.38 |
| m_sigma | 5.31 | 5.26443 |
| m_omega | 7.83 | 7.83 |
| m_rho | 7.70 | 7.7 |
| g_sigma | 9.82 | 11.4694 |
| g_omega | 11.8 | 14.6377 |
| g_rho | 3.42 | 4.6783 |
| g2 | −15.5 | −4.444 × 1.98 |
| g3 | 1.26 | 4.6076 |
| c3 | 72.6 | 84.5318 |

NN1 is the parameter set of Guo et al. (the default; active in the notebooks);
TM2 is the Sugahara–Toki set (provided as a commented alternative `modelpar`
block — swap it in to reproduce the TM2 comparison). TM2's `g2` is −4.444 fm⁻¹
converted to code units via 1 fm⁻¹ ≈ 1.98 HMeV.

## Installation

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Requires Python ≥ 3.9. PyTorch runs on CPU (float64 is required by the field
solver, so Apple MPS is not used; CUDA is used automatically when available).

## Reproducing the paper

Everything needed for the figures ships in the repo, so the two figure scripts
run out of the box:

```bash
python make_fig_maxwell_C12.py   # Fig. 1
python make_figs_eos_mr.py       # Figs. 2-5
```

Regenerating the intermediate results end-to-end:

1. **Wigner–Seitz EoS tables** — run the notebooks in `producting_Run/`
   (`jupyter lab`). Each notebook solves the cell for one seed nucleus across
   the density grid and writes `eos_*.dat` tables; the shipped checkpoints in
   `producting_Run/results/parameter/` provide converged warm starts. On a GPU
   server this uses CUDA; on a laptop it falls back to CPU.
2. **Maxwell-connected EoS** — `python eos_maxwell_connect.py <eosdir>`
   connects a family of composition branches with `eos_rmf.dat` into a single
   cold EoS (see the module docstring for the input conventions).
3. **Mass–radius tables** — `python run_dense.py` integrates the TOV equations
   over each connected EoS and regenerates `results/mr_dense_*.dat`
   (`tov_dense.py` validates its solver against the shipped `mr_pmu_*`
   reference tables).
